Build MCPs as simple agents

mcp.build is a community for open source MCPs that use the Hal9 agent shape — input() and print() — for easy deploy and interoperability. Built so humans and coding agents can contribute.

Why this shape

stdin / stdout

simple

No framework required. Read with input(), write with print(). Same code runs as chat, API, or MCP tool.

Deploy in one step

hal9

Push a folder, CI deploys to Hal9 when it changes. Local: hal9 deploy ./my-agent.

Agent-readable

claude · grok

Layouts, catalog, and rules live in plain files so Claude Code, Grok Build, and similar tools can open a PR without guesswork.

Contribute

Designed for coding agents (Claude Code, Grok Build, Cursor, Codex, …) and humans. Follow the checklist — no special tooling beyond Python and Git.

For agents: read root AGENTS.md and docs/llms.txt, then open a PR that only touches your new agent folder + deploy workflow.

  1. Create a folder One agent per top-level directory, e.g. my-tool/. Keep the name short, kebab-case.
  2. Add app.py Use input() / print() (or any stdin/stdout). Prefer no Hal9 package unless you need session state.
  3. Add deps + optional config requirements.txt if needed; hal9.yaml for welcome text.
  4. Wire deploy CI Copy .github/workflows/send-email.yaml, point paths and hal9 deploy at your folder.
  5. Register the agent Append an entry to docs/agents.json and mention it in the root README.

Expected layout

# minimum
my-tool/
  app.py              # input() → work → print()
  requirements.txt    # optional
  hal9.yaml           # optional welcome

# also update

docs/agents.json
README.md

Minimal agent

# my-tool/app.py
prompt = input()
# … call APIs, tools, models …
print(result)

Deploy workflow pattern

# .github/workflows/my-tool.yaml
on:
  push:
    branches: [main]
    paths:
      - my-tool/**
      - .github/workflows/my-tool.yaml

# job: pip install hal9 → checkout → if my-tool/ changed:
hal9 deploy my-tool --name my-tool --access public \
  --title "My Tool" --description "…"
